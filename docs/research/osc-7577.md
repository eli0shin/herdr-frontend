# OSC 7577: resuming programs after a restart

Ticket `055-osc-7577-agent-resume`, researched 2026-11-27 from live sources. Eli's question: Pi
supports OSC 7577 now, so can we drop the dotfiles resume hack (`fish/conf.d/hc-pi-resume.fish`
plus the `dotfiles.pi_session` labels), and where does support belong?

## Answer

- **Pi emits it from 1.7.0** (published 2026-11-27). This Mac runs 1.7.0 since 2026-11-27
  (`pi --version`; `~/.pi/agent/install/current-version`), and that install has the OSC 7577
  code.
- **herdr-core is the terminal that does the resuming.** It hands each terminal a token,
  checks the reports it gets back, keeps the resume command, and runs it when it brings back a kept
  terminal. This landed on herdr-core `master` in
  [#429](https://github.com/herdrdev/herdr-core/pull/429) (`1f90391`, 2026-11-26) and was
  hardened in [#433](https://github.com/herdrdev/herdr-core/pull/433) (`2e8043a`). The latest
  release, hc **0.1.22** (2026-11-22), predates both. Pi only comes back by itself once a release
  after 0.1.22 is installed.
- **libghostty-vt isn't involved.** herdr-core reads the sequence from the program's raw output
  with its own parser. libghostty-vt 1.0.2, which our viewer links, doesn't know OSC 7577 and
  drops it like any other OSC it doesn't recognize. Ghostty's `main` branch has no parser for it
  either.
- **herdr-frontend needed nothing new to make resume work.** Every pane it starts is already
  `keep: true`, and panes follow terminal addresses through a core restart. The client API didn't
  change: #429 only rewrote the description of `keep`. This ticket adds two guards:
  - a test that the viewer draws, answers and raises nothing for a report;
  - `hc` never gets a token that herdr-frontend inherited.
- **The dotfiles hack can go once the next herdr-core release is installed,** after one real
  reboot proves it (Pi 1.7.0 already is). Until then it is the only thing that resumes Pi. This ticket
  doesn't touch it (see [The dotfiles hack](#the-dotfiles-hack)).

## The protocol

The spec is the [Program Resume Protocol (OSC
7577)](https://www.superlogical.com/rex/docs/build/program-resume). Mitchell Hashimoto announced
it on 2026-11-25 with Rex, Superlogical's terminal, which shipped first. It was written together
with herdr's authors ([@herdrdev](https://x.latent.space/herdrdev): "herdr will support it in the
next update"). It is the resume counterpart of OSC 7501, the program status protocol that Pi and
herdr-core already use.

A program tells its terminal how to start it again:

```
ESC ] 7577 ; pid=<owner>:time=<unix seconds>:argv=<b64>,<b64>,...[:cwd=<b64>]:mac=<sha256 hex> ESC \
ESC ] 7577 ; pid=<owner>:time=<unix seconds>:clear=1:mac=<sha256 hex> ESC \
```

- **Token.** The terminal puts a random `OSC7577_TOKEN` (22 to 64 characters) in the
  environment of each pane's first process, with a new one each time the pane starts. `mac` is
  `sha256(<body before ":mac=">:<token>)`. The token is never sent itself. Raw text, `cat`ing a log
  and remote output can't make a record because they can't sign one. There is no query: a program
  that sees the variable reports, and one that doesn't stays silent. A multiplexer gives each of its
  panes its own token and never passes on its own.
- **Checks.** The terminal ignores a report whose `mac` is wrong or whose `time` is more than
  60 s from its own clock. It SHOULD check that `pid` is a live process of the same user running
  in that pane. A record ends when the owner exits on its own (with a grace of a second or two for
  shutdowns) or when the program sends `clear`.
- **Restoring.** After a restart the terminal MAY run `argv` in `cwd`, from the user's shell
  after its startup files have run, each element as one argument, never as shell source. A failed
  resume isn't retried. Only the command comes back: no screen modes, environment or shell state.
- **Program duties.** A program reports again whenever its command changes. It sends `clear`
  when the user quits, but never on SIGHUP or SIGTERM, since that is the moment the record is
  needed. It removes the token from the environment of anything it starts.

Terminals that support it: Rex; herdr-core `master`; herdr, the TUI (announced for its next
update); [phux](https://docs.phux.sh/program-protocol) and
[Workroom](https://codaset.dev/workroom/docs/guides/make-your-program-resume) document it too.
Programs that report it: Pi 1.7.0, [fast-agent](https://fast-agent.ai/guides/tui/),
[PiG](https://pi-in-go.dev/docs/latest/terminal-setup/), Hermes
([PR](https://github.com/NousResearch/hermes-agent/pull/160797)). Claude Code is resumed in Rex
through a session-start hook Rex installs. Native support is a [feature
request](https://github.com/anthropics/claude-code/issues/112408).

## What Pi 1.7.0 sends

From its [changelog and terminal setup docs](https://docs.pi.dev/latest/terminal-setup#program-resume),
checked against the published `@earendil-works/pi-coding-agent@1.7.0` bundle:

- Interactive mode reports only when `OSC7577_TOKEN` is set. It takes the variable out of its
  own environment at startup, so no tool, extension or shell it starts sees it.
- `argv` is `pi --session <id>`, plus `--agent-dir` / `--session-dir` when they aren't the
  defaults, plus the restriction and resource flags as typed (`--tools`, `-e`, `--skill`,
  `--system-prompt`, …). `cwd` is the session's folder and `pid` is Pi's own process. The report
  ends with `ESC \` and is at most 2048 bytes.
- It reports when a session starts, is resumed or forked, and when a new session gets its first
  message. It clears when a new session has no messages, when you quit (`Ctrl+D`, `Ctrl+C` twice,
  `/quit`), and when flags were typed in a folder other than the session's.

## Who does what

| Part | Role | State |
| --- | --- | --- |
| Pi | Reports `pi --session <id>`, clears on quit | 1.7.0, installed on this Mac |
| herdr-core | The terminal: sets the token per terminal, parses and checks reports in the output stream, stores records privately with its registry, and reruns the command when it brings back a kept terminal | `master` since #429/#433; not in hc 0.1.22 |
| libghostty-vt | Nothing. The core has its own parser; the viewer's copy ignores the OSC | 1.0.2 has no OSC 7577 command |
| herdr-frontend | Starts every pane `keep: true`, follows addresses through restarts, and draws the reports as nothing | Done, plus this ticket's guards |

How herdr-core brings Pi back (`resume.rs`, `resume/launch.rs`, `platform/unix_resume.rs` on
`master`):

- **Record.** A report counts only from a process in the terminal's own process tree, owned by
  the same user. Records are keyed by pid plus start time, so a reused pid doesn't count. When a
  parent and its child both reported, the outer one is chosen. Records are saved privately with the
  terminal registry, and resume turns itself off if the state folder isn't private.
- **Relaunch.** A kept terminal that lost its program (reboot, crash, `hc server stop`) gets a
  one-use launch file, so a command can't run twice. For fish, the program runs from the user's
  interactive login shell, as its job: `fish -lic '"$argv[1]" __resume "$argv[2]"; exec "$argv[3]"
  -li'`. When Pi quits, an interactive fish takes its place. A program that was the terminal's first
  process replaces that shell (`exec`) instead. If the owner is still alive, nothing starts. A
  terminal without a record gets a shell, as before.
- **Final ends.** An ordinary exit or `hc kill` stays final. Closing a pane in herdr-frontend kills
  its terminal, so Pi doesn't come back there. Parking turns `keep` off, so a parked terminal isn't
  brought back either, the same as in Herdr app.

### herdr-frontend's part

- `terminal.run` sends an explicit `env` (`TERM`, `COLORTERM`, `TERM_PROGRAM`) and
  `keep: true`. A newer core also drops any `OSC7577_TOKEN` a client sends.
- The viewer gets the same output bytes. `terminal/tests/vt.rs::program_resume_reports_are_left_to_the_core`
  checks that a report, with either terminator, leaves no text, reply or event. A later
  libghostty-vt that learns OSC 7577 can't make the viewer act on reports without failing that
  test.
- `herdr-client`'s `HcCommand` removes `OSC7577_TOKEN` from every `hc` it runs
  (`transport.rs::hc_never_gets_a_resume_token`). Without that, starting herdr-frontend from a
  terminal that has a token gives it to `hc connect`, and to any core `hc connect` starts. With
  hc 0.1.22 that core passes its environment to every terminal it runs, so all panes would carry the
  outer pane's token. That breaks the spec's "never pass on a token" rule. The case happens with
  `just run` from a herdr-core terminal once the core supports OSC 7577, or when starting from Rex.
  Newer cores also strip it at their end.
- There is no setting and no UI. The core decides which reports to trust and when to resume.

## The dotfiles hack

`hc-pi-resume.fish` (read, not changed):

1. `hc-session-label.ts` labels the terminal with Pi's session file and a token of the shell
   that Pi ran under.
2. On the first prompt of a reopened terminal, the shell finds a session labeled under another
   shell's token and types `PI_PROGRAM_STATUS=1 pi --session <file>`.

From the code, without running it, this is how it interacts with herdr-core's resume:

- **No double start.** Under herdr-core's resume, the `fish -lic` that starts Pi never draws a
  prompt, so the hack's prompt hook doesn't fire. The `fish -li` that replaces Pi inherits
  `DOTFILES_HC_SHELL` for this terminal and returns early. A terminal with no record gets a plain
  shell, and the hack resumes Pi as before. Until the hack is removed it acts as a fallback.
- **Status after a resume.** The hack sets `PI_PROGRAM_STATUS=1` because Pi only sends OSC 7501
  after the terminal answers its query. Early in a shell's life, the reply to fish's own startup DA
  query can reach Pi first, and Pi then decides the terminal can't take reports. A Pi resumed by
  herdr-core starts from `fish -lic` without that variable and could lose the same race. It would
  then run without a status in the sidebar. Check this on the first real resume. If it happens, the
  fix is in Pi's detection or in Eli's environment (`PI_PROGRAM_STATUS=1` in herdr-core
  terminals), not in herdr-frontend.

## Left for herdr-core and the dotfiles

1. **herdr-core:** release `master` (anything after `2e8043a`), then `hc update`.
2. **Pi:** done. 1.7.0 is installed on this Mac.
3. **Prove it:** use an isolated core (`HC_SESSION=<name>`), never the real one (`AGENTS.md`):
   - start a kept terminal and check `test -n "$OSC7577_TOKEN"` in it;
   - run Pi there and send a message;
   - `HC_SESSION=<name> hc server stop`, then start that core again;
   - Pi should be back in the same session. A real reboot is the final check.
4. **Dotfiles:** remove `hc-pi-resume.fish`, the `dotfiles.pi_session` / `pi_shell` labels and
   `hc-session-label.ts`'s part in them, in a separate change.
